# 返信

## 要点

- Discord の「**返信**」は、**チャンネルにふつうに書きこむのと同じ**。そこに「どのメッセージへの返事か」という印が付くだけ
- 返事は、元のメッセージの下にまとまる**のではなく**、チャンネルの**いちばん下**(いつもの流れ)に出る。返事の上に、元のメッセージが小さく引用され、押すと元のメッセージに飛ぶ
- 返信すると、ふつうは元のメッセージを書いた人に**通知(メンション)が届く**。返信ごとに「@オン/オフ」で切れる
- Slack の「スレッドで返信する」のように、返事を1か所にまとめたいときは、返信ではなく**スレッド**を使う([21-threads.md](21-threads.md))
- いちばん近いのは、LINE の「リプライ」

この記事は、ネットの情報からまとめたもの。実機では確認していない。日本語の画面の名前は、非公式の日本語の解説からとったもので、今の画面と違うことがある。

## 返信の見え方

たとえば、Aさんの「明日の集合は何時?」に、Bさんが返信すると、チャンネルには次のように出る。

```
Aさん:明日の集合は何時?
Cさん:おなかすいた
Dさん:新しいゲーム買った
  ┌ @Aさん 明日の集合は何時?        ← 元のメッセージが小さく引用される(押すと飛ぶ)
Bさん:10時です                      ← 返事はいちばん下に出る
```

- 返事は、ほかの話と同じ流れに並ぶ。**返事がいくつ付いても、まとまらない**
- 元のメッセージが上に流れてしまっていても、引用の部分を押せば、元のメッセージまで戻れる
- 元のメッセージが消されると、引用の部分は「元のメッセージは削除されました」のような表示になる、と思われる(未確認)

## 手順

### パソコン

1. 返事をしたいメッセージにマウスを重ねる
2. メッセージの右上に出るボタンの中の「**返信**」(左向きの矢印)を押す。メッセージを右クリックして「返信」を選んでもよい
3. 入力欄の上に、だれに返信しているかが出る。ふつうに書いて送る

- やめたいときは、入力欄の上の「×」を押す(未確認)

### スマホ

1. 返事をしたいメッセージを**長押し**する
2. 「**返信**」を押す
3. ふつうに書いて送る

- メッセージを**スワイプ**しても返信できる、という情報がある(非公式の情報。どちら向きか、iPhone と Android でちがうかは未確認)

## 通知(メンション)のオン/オフ

- 返信すると、**ふつうは元のメッセージを書いた人にメンションとして通知が届く**(公式サポート)
- 返信を書いているときに、入力欄の上の「**@オン**」を押して「**@オフ**」にすると、その返信では通知が届かない(公式サポートでは、返信ごとに切れるとしている。日本語の画面の名前は未確認)
- **いつもオフにしておく設定はない**。毎回切るしかない(公式フォーラムで「ふつうオフにしたい」という要望が何度も出ている。2026年の今も無いかは未確認)
- 通知がオフでも、返信の印(引用)は付く。相手がチャンネルを見れば、自分への返事だとわかる

### 気をつけること

- 何でも返信で返すと、そのたびに相手に通知が届く。ちょっとした返事が多いときは「@オフ」にするか、返信を使わずにふつうに書く
- 逆に、相手に必ず気づいてほしいときは、返信のまま(@オン)にする
- 通知を受ける側の設定は [02-notifications.md](02-notifications.md)

## Slack とのちがい

Slack に慣れている人がいちばん戸惑うところ。Slack の「スレッドで返信する」と、Discord の「返信」は**別のもの**。

| | Slack の「スレッドで返信する」 | Discord の「返信」 |
|---|---|---|
| 返事が出る場所 | 元のメッセージの下にまとまる(右に開く) | **チャンネルのいちばん下**。ほかの話と同じ流れ |
| 返事がいくつも付いたら | 1か所にまとまる | まとまらない。流れの中にばらばらに出る |
| 元のメッセージとのつながり | 元のメッセージに返事の数が出る | 返事の上に、元のメッセージが1行だけ引用される |
| 通知 | スレッドに参加している人に届く | 元のメッセージを書いた人に届く(@オフで切れる) |

- Slack のスレッドに近いのは、Discord の**スレッド**の方。くわしくは [21-threads.md](21-threads.md) の「Slack のスレッドとのちがい」
- Slack の情報は、一般に知られていることからまとめた(未確認)

## 返信・スレッド・引用・転送の使い分け

| やりたいこと | 使うもの | 通知 |
|---|---|---|
| 1つのメッセージに、ひとこと返す | **返信** | 元の人に届く(@オフで切れる) |
| 話が長くなりそう。チャンネルの流れを邪魔したくない | **スレッド**([21-threads.md](21-threads.md)) | スレッドに入っている人に届く(未確認) |
| 文の一部を引いて話す | **引用**:行の頭に `> ` を付けて書く | 届かない |
| メッセージを、別のチャンネルや人に送る | **転送** | 送った先の人に届く(未確認) |

- **引用**は、`> ` の後ろの文が、左に線の付いた引用の形で出るだけ。元のメッセージとはつながらない(押しても飛ばない)
- **転送**は、メッセージを別のチャンネルや DM に送る機能。くわしくは下の「転送」

## 転送

メッセージを、別のチャンネルや DM に送る機能。Slack で「投稿のリンクをコピーして、別のチャンネルに貼る」手作業に近いが、しくみはちがう。リンクは**場所を教える**もの、転送は**中身の写しを送る**もの。

- 送ったものには「**転送**」の印が付く(公式サポート)
- 送ったときの**写し**になる。元のメッセージを直しても、転送したものは変わらない(公式サポート)
- 一度に送れる相手は**5つまで**(非公式の解説)
- 日本語の画面の名前と、転送のしかた(メッセージのどのボタンから送るか)は未確認

### 転送元へのリンク

転送したものには、元のメッセージへのリンクが付く。ただし、**見える人が限られる**(公式サポート)。

| 転送先で見ている人 | 写し(中身) | 元のメッセージへのリンク |
|---|---|---|
| 元のチャンネルに入れる人 | 見える | 見える。押すと元のメッセージに飛べる |
| 元のチャンネルに入れない人 | **見える** | 見えない(元が公開サーバーなら見える) |

- リンクが写しのどこに、どんな形で出るかは未確認

### リンクを貼るのとのちがい

| | メッセージのリンクを貼る | 転送 |
|---|---|---|
| 送られるもの | 元のメッセージの**場所** | 元のメッセージの**中身の写し** |
| 元のメッセージを直したら | 開くと、直したあとの中身が見える | 変わらない(送ったときのまま) |
| 元のメッセージが消されたら | 開けなくなる | 写しは残る、と思われる(未確認) |
| 元のチャンネルに入れない人 | 中身を見られない | 中身を見られる |
| 書いた人の名前 | 元のメッセージを開けばわかる | 写しには出ない、という情報がある(非公式の情報。未確認) |

- Discord でも、メッセージを右クリックして「**メッセージリンクをコピー**」を選び、別のチャンネルに貼れば、Slack と同じやり方になる(画面の名前は未確認)
- 元のチャンネルに入れる人どうしで「この話の続き」と場所を示したいときは**リンク**、中身を入れない人にも見せたいときは**転送**、と使い分ける

### 気をつけること

- プライベートなチャンネルのメッセージを公開のチャンネルに転送すると、**入れない人にも中身が見えてしまう**
- 自分のメッセージを転送されないようにする設定はない、という情報がある(非公式の情報。未確認)
- 転送された写しは、元のメッセージを消しても残る、と思われる(未確認)。見せたくないものは、転送されうると考えておく

### 使い方の例:ちがうチャンネルに来た問い合わせを、本来のチャンネルへ誘導する

転送やリンクは「知らせる」ための機能で、**話の場所を移す機能ではない**。そのため、転送しただけだと、元のチャンネルと転送先の両方で話が続いてしまい、混乱しやすい。Discord には、メッセージを別のチャンネルに**移す**機能はない(公式フォーラムに「Move Messages」の要望が出ている)。人の手で、次のように誘導する。

大事なのは、**元のチャンネルで話を終わらせて、行き先をはっきり示すこと**。

1. **転送先**(本来のチャンネル)に、話の入り口を作る
   - 転送して、続けて「**@Aさん** の質問をこちらに移しました」と書き、本人をメンションする(写しには書いた人の名前が出ないかもしれないため)
   - 転送の代わりに、自分で書き直してもよい:「@Aさん から、〇〇についての質問です」+元のメッセージのリンク
2. **元のチャンネル**で、元のメッセージに**返信**する
   - 「この話は #本来のチャンネル で続けます → (転送先のメッセージのリンク)」
   - 返信なので、元の人に通知が届く。リンクを押せば、そのまま転送先に行ける
3. 元のチャンネルでは**スレッドを作らない**。もう作られていたら、同じように行き先を書いてから、**ロックしてアーカイブ**する(「スレッドの管理」の権限が要る。[21-threads.md](21-threads.md))

元のチャンネルの最後に「続きはあちら」が残っていれば、後から来た人も迷わず、二重にやりとりしなくて済む。

そもそも間違いを減らすには:

- チャンネルの**トピック**(説明)に「問い合わせは #〇〇 へ」と書いておく
- 問い合わせを**フォーラムチャンネル**にまとめる。1件ごとに投稿が立つので話が混ざらず、ガイドラインやタグで何をどこに書くかも示せる([20-forum.md](20-forum.md))
- メッセージを移せる外部の Bot もあるらしい。Discord の公式機能ではない(未確認)

この誘導のしかたは、機能のしくみから考えた使い方の例で、実機では試していない。
