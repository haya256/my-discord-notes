# Webhookの作り方

## 要点

- Webhookは、外部のプログラムやサービスからチャンネルにメッセージを投稿するためのURL
- 作るには「ウェブフックの管理」権限が必要
- **WebhookのURLは秘密情報**。知っている人は誰でもそのチャンネルに投稿できる

## 手順(PC)

1. 左端のサーバーアイコンを右クリック →「サーバー設定」をクリック
2. 左メニューの「アプリ」の下にある「連携サービス」を開く
3. 「ウェブフック」→「新しいウェブフック」を押す。すぐにウェブフックが作られ、設定欄が開いた状態で表示される(名前は「Spidey Bot」などが自動で付く)
4. 「お名前」と「チャンネル」(投稿先)を設定する
5. 画面下に「注意:保存していない変更があります!」と出るので、「変更を保存する」を押す
6. 「ウェブフックURLをコピー」して、外部サービス側に貼る

チャンネル名の横の歯車(チャンネルの編集)→「連携サービス」からも作れる。

## 使い方の例

```bash
curl -H "Content-Type: application/json" \
  -d '{"content": "テスト投稿です"}' \
  "<ウェブフックURL>"
```

成功すると、画面には何も表示されない(HTTPステータスは204)。チャンネルには、ウェブフックに付けた名前で「アプリ」のラベル付きで投稿される。

## Webhook と Bot の違い(どちらを使うか)

「このチャンネルに外から書き込ませたい」ときは、まずWebhookで足りるかを考える。

| | Webhook | Bot |
|---|---|---|
| できること | 決めたチャンネルに**投稿するだけ** | 投稿、メッセージを読む、コマンドに反応する、など |
| 管理者がすること | ウェブフックを作り、**URLを相手に渡す** | Botの作者が用意した**招待リンクから、Botをサーバーに追加する**(管理者から渡すものはない) |
| 書き込めるチャンネル | 設定した1つのチャンネルだけ | チャンネルの権限設定で、管理者が絞る |
| 秘密情報 | WebhookのURL(管理者が作って渡す) | Botのトークン(Botの作者が持つ。管理者が作ったり受け取ったりするものではない) |

- 通知を流したいだけ(GitHubの更新通知、サーバーの監視アラートなど)→ Webhook
- 会話に反応させたい、コマンドで操作したい → Bot

この節は一般的な知識をまとめたもので、実機では未確認。

## メモ

- 実機で未確認:「ウェブフックの管理」権限が必要なこと、チャンネルの歯車からも作れること、1つのチャンネルに複数作れること
- URLをGitHubなどの公開リポジトリに書かない。漏れたら、そのWebhookを削除して作り直す(削除は設定欄の「ウェブフックを削除」)
- 1つのチャンネルに複数のWebhookを作れる。用途ごとに分けると、どこから来た投稿かわかりやすい
