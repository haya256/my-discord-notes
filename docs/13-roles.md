# ロールについて

## 要点

- **ロール**は、サーバーのメンバーに付ける「役職」。1人に何個でも付けられる
- ロールには、主に3つの働きがある:**できることを決める(権限)**、**見た目を変える(名前の色・メンバー一覧での分け方)**、**まとめて呼ぶ(メンション)**
- 権限は**足し算**。付いているロールのどれか1つで許可されていれば、その人はできる
- ロールには**上下の順番**がある。順番が効くのは「名前の色」と「誰が誰を管理できるか」。**権限の計算には順番は関係ない**
- 「このチャンネルだけは会員しか見られない」のような設定は、**チャンネルごとの上書き**で作る

## ロールとは

ロールは、**名札と鍵束がセットになったもの**だと考えるとイメージしやすい。

- **名札**:付けている人の名前に色が付いたり、メンバー一覧で「運営」「メンバー」のようにグループ分けされたりする。周りから見て「この人は運営の人だ」とわかる
- **鍵束**:そのロールを持っている人は、決められた部屋(チャンネル)に入れたり、決められた操作(メッセージを消す、人を追い出す など)ができたりする

人ごとに「この人はこれができる」と1人ずつ決めるのではなく、**ロールに「できること」を決めておき、人にはロールを付ける**。人が増えても、ロールを付けるだけで済む。

### 例:ゲーム仲間のサーバー

| ロール | 名札(見た目) | 鍵束(できること) | 付ける人 |
|---|---|---|---|
| 管理人 | 赤い名前。一覧のいちばん上に表示 | サーバーの設定を変える、ロールを作る | サーバーを作った人と、もう1人 |
| モデレーター | 青い名前 | 荒らしのメッセージを消す、迷惑な人を追い出す | 手伝ってくれる数人 |
| メンバー | 色なし | ふつうに書き込む、通話に入る | 自己紹介を済ませた人 |
| Apex / マイクラ | 色なし | なし(呼び出し用) | そのゲームを遊ぶ人。本人が選んで付ける |

- 「Apex」「マイクラ」のロールには権限を持たせない。**一緒に遊ぶ人を呼ぶためのロール**として使い、「@Apex 今から遊べる人?」のようにメンションする
- 会員制サーバーでは「会員」ロールを作り、会員だけが見られるチャンネルを用意する。会員サービスと連携して、ロールを自動で付けることもできる([09-membership-services.md](09-membership-services.md) を参照)

## ロールの3つの働き

### 1. 権限(できること)

- 「チャンネルを見る」「メッセージを送る」「メッセージを管理(ほかの人の投稿を消す)」「メンバーをキック」など、細かい項目ごとにオン・オフを決める
- **付いているロールの権限は足し算になる**。たとえば「メンバー」と「モデレーター」の両方を持っている人は、両方のロールでできることを全部できる
- 「管理者」(英語版は Administrator)の権限は特別で、**すべての権限を持ち、チャンネルごとの制限も無視する**。むやみに付けない

### 2. 見た目(名札)

- **名前の色**:ロールに色を付けると、チャットでその人の名前がその色になる。ロールを複数持っているときは、**いちばん上のロールの色**になる
- **メンバー一覧で分けて表示**:設定をオンにしたロールは、メンバー一覧(画面右)で、ほかの人とは別のグループとして表示される
- **ロールアイコン**:名前の横に小さいアイコンを付けられる。サーバーブーストのレベル2から使える([12-server-boost.md](12-server-boost.md) を参照)

### 3. メンション(まとめて呼ぶ)

- 「@ロール名」と書くと、そのロールを持っている人全員に通知が届く
- 誰でもメンションできるようにするかどうかは、ロールごとに設定する。大人数のロールを誰でも呼べるようにすると、いたずらで一斉通知される心配がある

## @everyone ロール

- **全員が最初から持っている、見えないロール**。サーバーに入った人は、何もしなくてもこのロールを持っている
- ロールを何も付けていない人ができることは、@everyone の権限で決まる。つまり **@everyone は「サーバーの全員の土台」**
- 新しく作ったロールは、作ったときの @everyone の権限をもとに始まる
- @everyone に権限を足すと、**サーバーの全員**に効く。1つの困りごとを直すつもりで @everyone に権限を足すと、ほかの所で思わぬ穴が開くことがある

## ロールの順番(上下関係)

ロールの一覧は上から順に並んでいて、ドラッグで並べかえられる。新しく作ったロールは、@everyone のすぐ上(いちばん下)に入る。

**順番が効くこと**
- **名前の色**:いちばん上のロールの色が使われる
- **誰が誰を管理できるか**:ロールを管理する権限を持っていても、**自分のいちばん上のロールより下のロール**しか付けたり編集したりできない。キックやBANも、相手のいちばん上のロールが自分より下のときだけできる
- **Botも同じ**:Botにも専用のロールが付く。Botのロールより上のロールを持つ人には、Botは何もできない。「Botがロールを付けてくれない」ときは、Botのロールの位置を確認する

**順番が効かないこと**
- **権限の計算**。上にあるロールの「拒否」が、下にあるロールの「許可」に勝つ、ということはない(下の「チャンネルごとの上書き」を参照)

## チャンネルごとの上書き

サーバー全体のロールの権限とは別に、**チャンネルごとに「このロールは、このチャンネルでは見られない/見られる」と上書き**できる。カテゴリーに設定すると、その中のチャンネルにまとめて効く(カテゴリーと同期している場合)。

### 例:会員だけが見られるチャンネル

1. 「会員限定」チャンネルの設定で、**@everyone** の「チャンネルを見る」を**拒否**にする → 誰も見られなくなる
2. 同じチャンネルで、**会員**ロールの「チャンネルを見る」を**許可**にする → 会員ロールを持っている人だけ見られる

### 上書きが効く順番

Discord は、次の順番で権限を決める。**あとの方が強い**。

1. サーバー全体での、その人のロールの権限(足し算)
2. そのチャンネルでの **@everyone** の上書き
3. そのチャンネルでの **その人が持っているロール** の上書き(全部のロールの「拒否」をまとめて当ててから、「許可」をまとめて当てる)
4. そのチャンネルでの **その人個人** の上書き

- 3. のとおり、**ロール同士では「許可」が勝つ**。ロールの順番は関係ない
- 個人への上書きがいちばん強いが、あとから見て分かりにくいので、なるべくロールで設定する

### よくある落とし穴:「書き込み禁止」ロールが効かない

- 荒らし対策で「書き込み禁止」ロールを作り、各チャンネルで「メッセージを送る」を**拒否**にした
- でも、その人が「メンバー」ロールも持っていて、そのチャンネルで「メンバー」に「メッセージを送る」を**許可**していると、**許可が勝って書き込めてしまう**
- 「書き込み禁止」ロールをいちばん上に置いても変わらない(順番は権限の計算に関係ないため)
- 対策:チャンネルでは「メンバー」に許可の上書きをしない(サーバー全体の設定に任せる)。またはDiscordの「タイムアウト」機能を使う

## 手順(PC)

### ロールを作る

1. サーバー名を押して「サーバー設定」を開く
2. 左メニューの「ロール」を開き、ロールを作るボタンを押す
3. 名前と色を決め、必要なら「メンバー一覧で分けて表示」「メンションを許可」の設定をする
4. 権限のタブで、そのロールでできることをオンにする
5. 保存する

### ロールを付ける

- メンバー一覧で相手を右クリック → 「ロール」から付けたいロールにチェックを入れる
- または、ロールの設定画面の「メンバー」のタブから、まとめて追加する

- 日本語版の画面での名前は未確認です。上の手順は流れの目安

## よくある失敗

- **見た目用のロールに権限を持たせる**:色を変えるだけのロールや、本人が選んで付けられるロールに権限を付けると、誰でもその権限を手に入れられてしまう
- **@everyone に権限を足して直そうとする**:全員に効くので、別の所で穴が開く
- **Botのロールをいちばん上に置く**:Botが乗っ取られたときの被害が大きくなる。Botの仕事に必要な位置に置く
- **手伝いの人に「チャンネルの管理」を付ける**:うっかりチャンネルを消してしまうことがある
- **古い上書きが残っている**:チャンネルだけ思った通りに動かないときは、そのチャンネルの上書きを確認する([01-basics.md](01-basics.md) のメモも参照)
